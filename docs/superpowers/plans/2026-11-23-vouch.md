# Vouch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a conforming open agentic website whose agents cannot assert that food is safe — a pure checker owns that claim, a gate enforces it, and the spec's §6 refusals are visible and testable.

**Architecture:** Three layers that never merge. `src/safety/` is pure and knows nothing about models or the DOM. `src/gate/` is the only path from a model response to the screen. `src/site/` is an ordinary deli website that works with no agent at all. The agent network is data (`public/vouch.network.json`), never code.

**Tech Stack:** TypeScript, Vitest, Vite, vanilla DOM (no framework — the spec requires plain browser execution). Node 22+ for the upstream skill and the conformance CLI.

**Spec:** [`docs/SPEC.md`](../../SPEC.md) · conformance target [`docs/mvp-spec-2026-11-23.md`](../../mvp-spec-2026-11-23.md) · event constraints [`docs/EVENT.md`](../../EVENT.md)

## Global Constraints

- **No server-side code.** Tenet Two: the network executes in the browser. A backend breaks conformance.
- **No model may emit a safety verdict.** Only `verdictFor` produces `Finding`s; only the gate renders them.
- **BYOK.** The user supplies provider and key (Tenet Three). The site never ships a key and never pays for inference.
- **Published artifacts are public GET with CORS**, HTTPS in production, loopback HTTP locally (§3.3, §3.4).
- **`unknown` is a real verdict**, never coerced to `safe`.
- **Private context is deny-by-default** across site boundaries; a network MUST name any field allowed to cross (§2.1).
- Node **22+**. Conformance is judged against the **pinned** spec copy.

## Review Focus

Input classes the spec implies that no task's tests would otherwise exercise:

1. **An item with no ingredient data at all** — must be `unknown`, never `safe`. The most likely real-world input and the most dangerous wrong answer. Pinned in Task 2.
2. **A restriction the menu has never seen** ("I avoid sesame" when no item lists sesame) — must not silently return `safe` for everything. Pinned in Task 2.
3. **A model response that asserts safety using a synonym** ("dairy-free", "you'll be fine with", "no gluten in this") — the gate must catch phrasing it was not literally written for, or fail closed. Pinned in Task 3.
4. **A peer that returns prose instead of ingredient data** — the cross-origin answer must degrade to `unknown`, not inherit the peer's confidence. Pinned in Task 8.
5. **A derived allergen two hops deep** (`brioche → butter → dairy`) — the `via` chain must name every hop, since a one-hop check would call brioche dairy-free. Pinned in Task 2.

### Task 2: The checker

**Files:** Create `src/safety/derive.ts`, `src/safety/verdict.ts` · Test `tests/verdict.test.ts`

**Interfaces:**
- Consumes: everything from Task 1.
- Produces: `allergensOf(ingredient: string, menu: Menu): { allergen: string; via: string[] }[]` and `verdictFor(item: MenuItem, restrictions: Restriction[], menu: Menu): Finding`.

- [ ] **Step 1: Write the failing tests** — these five are the specification of the function:

```ts
test("an item with no ingredient data is unknown, never safe", () => {
  expect(verdictFor(itemWithNoIngredients, [dairyFree], menu).verdict).toBe("unknown");
});

test("a restriction the menu has never seen does not make everything safe", () => {
  const all = menu.items.map(i => verdictFor(i, [sesameFree], menu));
  expect(all.every(f => f.verdict === "safe")).toBe(false);
});

test("a derived allergen names every hop that led to it", () => {
  const f = verdictFor(briocheBurger, [dairyFree], menu);
  expect(f.verdict).toBe("unsafe");
  expect(f.because?.via).toEqual(["brioche_bun", "brioche", "butter", "dairy"]);
});

test("safe findings carry no because, unsafe and unknown always do", () => { /* … */ });

test("the whole menu against every restriction never throws and never returns undefined", () => {
  for (const i of menu.items) for (const r of RESTRICTIONS)
    expect(["safe","unsafe","unknown"]).toContain(verdictFor(i, [r], menu).verdict);
});
```

- [ ] **Step 2: Run to verify they fail.**
- [ ] **Step 3: Implement `allergensOf`** — transitive closure over `contains`, accumulating the `via` path, with cycle protection.
- [ ] **Step 4: Implement `verdictFor`** — `unknown` when the item has no ingredients or any ingredient is absent from the table; `unsafe` on the first match, reporting the earliest; otherwise `safe`.

### Task 3: The gate

  expect(shown).not.toMatch(/dairy-free/);
  expect(refusals[0].claimed).toBe("dairy-free");
});

test("a claim backed by a matching finding is allowed through", () => { /* … */ });

test("synonyms for a safety assertion are caught", () => {

test("a claim the detector cannot parse fails closed", () => {
